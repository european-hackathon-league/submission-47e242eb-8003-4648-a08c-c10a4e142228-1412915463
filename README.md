# PM

A dependency-free prototype for turning automotive customer evidence into cited, context-sensitive requirements and preserving the reasoning behind each decision.

## Run

Requires Node.js 20+ and PowerShell 5+.

```powershell
$env:OPENAI_API_KEY='your-api-key'
# Optional; defaults to gpt-4o-mini
$env:OPENAI_MODEL='gpt-4o-mini'
node server.mjs
```

Open `http://localhost:4173`. Wait for the setup button to change from **Loading verified evidence…** to **Generate evidence-backed requirements** before continuing.

Do not launch `public/index.html` with a static-only preview server: stakeholder interpretation requires the Node API routes. If the header reports an outdated or missing PM API, stop the previous process with `Ctrl+C`, run `node server.mjs` again, and hard-refresh the browser.

The API key is read only by the Node server and is never returned to or stored by the browser. Do not place an API key in `public/`, source control, or browser `localStorage`.

To regenerate the normalized evidence file from the supplied archive:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\ingest-evidence.ps1
```

Run verification with:

```powershell
node --test
```

## Demonstration

1. Keep BMW 5 Series / G60 and United States selected.
2. Enter the target months, available people, and deadline importance.
3. Generate the requirements.
4. Select a feature group and open **Evidence & reasoning**.
5. Inspect the separate existence and ranking explanations and exact workbook-row citations.
6. Return to setup, change the deadline context, and regenerate to observe ranking changes.
7. Open **Check feasibility**, review the suggested owner and editable unsent email. You can dictate rough email notes and use **Create email from notes** without losing the default draft.
8. Paste `Feasible, but it requires an additional three months.`
9. Select **Process Feedback & Recalibrate**. Review the structured outcome, confidence, conditions, constraints, and timing.
10. Confirm the interpretation. Feasibility-only updates can recalibrate the group but are not written to **Decision memory**.
11. Select **Approve**. A decision note is optional; the approval and its supplied or default reason are stored for that exact vehicle and market.

Requirements are organized into four BMW vehicle domains: **Interior & Comfort**, **Exterior & Utility**, **Digital Experience & Controls**, and **Driving & Powertrain**. This keeps the review surface coherent while still ranking no more than ten requirements inside each domain.

Within those four stable navigation domains, PM derives evidence-based outcome clusters such as seating comfort, cargo access, connected access, parking confidence, and ride and handling. PMs can rename, split, merge, reorder, and move requirements without losing their citations.

## Grounding and provenance

`scripts/ingest-evidence.ps1` reads the supplied ZIP and `competitor_bmw_format.xlsx`. It creates `data/evidence.json` with exact filename, sheet, source row, original feedback ID, vehicle, market, classification, and original text. It also creates `data/context.json`, containing 1,003 customer-study rows, 12 sales-volume rows, 132 competitor signals, 13 competitor price references, source-file metadata, and verified PDF page counts. All nine supplied files are copied to `data/sources/` for direct inspection. The current generated feedback store contains 13,771 classification rows.

Frequency is calculated from unique feedback IDs within a feature, not spreadsheet rows. This prevents one comment assigned to several classifications from being presented as several customers. Low-quality and unclassified feedback remains in the evidence store but is excluded from requirements.

Requirement language, feature grouping, ownership routing, competitor-signal matching, and time-to-market fit are generated by deterministic, inspectable prototype logic. The application remains demonstrable without an API key. OpenAI-assisted email redrafting and stakeholder-response interpretation are disabled until the server key is configured.

## Current prototype boundaries

- Feedback, customer-study, sales-volume, original option-list, and competitor benchmark files are ingested. Ranked claims attach matching feedback, study, competitor, and vehicle/market sales records with workbook-row citations; competitor citations also link to the original external source recorded in the workbook.
- Original PDFs and verified page counts are available, but PDF text extraction is intentionally omitted because no reliable parser is installed. No PDF content or page citation is fabricated.
- Requirement grouping and planning estimates remain deterministic demo logic. Stakeholder-response interpretation and email drafting use the OpenAI Responses API. Competitor inputs come from the supplied, row-cited workbook rather than a separate market-intelligence tab.
- Only requirement approvals, approvals with conditions, and rejections containing a reason are exposed and appended as Decision Memory records. They are mirrored in browser storage; a production deployment should add authentication, signatures, backups, and formal retention controls.
- One approved record explicitly labeled **Team-authored demo history** seeds the memory experience. It is never presented as a verified BMW decision. The unresolved demo record is excluded from Decision Memory.
- Email is drafted only. The application does not send external messages.

## Architecture

- `scripts/ingest-evidence.ps1`: read-only archive ingestion and normalization
- `data/evidence.json`: generated evidence store with source lineage
- `src/engine.mjs`: grouping, deduplication, ranking, citations, and routing
- `src/openai.mjs`: stakeholder interpretation, grounded email drafting, and cited web research
- `public/`: application workflow and interface
- `server.mjs`: dependency-free static server
- `test/`: grounding and ranking invariants

The implementation is deliberately inspectable: deterministic frequency and ranking calculations are separated from natural-language explanations, and every displayed citation resolves to an ingested evidence record.
